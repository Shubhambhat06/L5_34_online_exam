# Lab 5 – Reflection

**1. Which issues were easiest to fix, and which were hardest?**
The easiest were the mechanical ones: Flake8's whitespace and blank-line errors, Pylint's naming and docstring messages, and the `elif` after `return`. Each message points at a line and says what to change. The hardest was the Bandit B605 finding. Deleting `os.system` was easy; making `lock_screen` genuinely safe took several decisions: an argument list instead of a shell, validating the host name, using `--` so a host starting with `-` can't be read as an ssh option, and resolving the `ssh` binary with `shutil.which`. The fix then triggered two new Low notices (B404, B603), and I had to decide whether suppressing them with `# nosec` was justified. I judged that it was, because the input is validated and no shell is involved, and I wrote the reason next to each comment.

**2. Did the tools report any false positives?**
Not strictly, but some findings were low-value in context. B311 (`random.choice`) is only a real risk if the bonus question must be unpredictable, which I decided it should be, so I switched to `secrets.choice`. B105 flagged a "password" that is a demo placeholder, but a secret committed to source is a bad habit either way, so I moved it to an environment variable. B404/B603 are informational once the call is safe, so I suppressed those two specifically rather than blanket-ignoring Bandit. Conversely, the tools missed two real bugs I found by reading the code: `topper()` crashes when no one has been graded, and `main()` runs on import.

**3. How would you integrate these tools into a real development workflow?**
Run Flake8 and Pylint as a pre-commit hook so style and quality problems never reach the repository, and run all three in CI (e.g. GitHub Actions) on every pull request, failing the build on any Bandit High/Medium finding and on a Pylint score below an agreed threshold. Configuration (`.pylintrc`, `setup.cfg`/`tox.ini` for Flake8, a Bandit config) should live in the repo so everyone gets the same rules, and any `# nosec` or `# pylint: disable` must carry a written justification and be reviewed.

**4. What tangible improvements did you see in the code?**
Pylint went from 5.65 to 10.00, and Bandit from 2 High + 2 Low findings to none. Concretely: a command-injection hole is closed, MD5 is gone, no secret is committed in source, the shared mutable default no longer leaks state between calls, the code follows PEP 8 naming and layout, every function is documented, `topper()` no longer crashes on empty input, and the module can be imported without side effects. Program output is unchanged, which I checked against a baseline run before and after each commit. One caution: a clean report is not proof of correct code. Two of the bugs I fixed were invisible to all three tools.
